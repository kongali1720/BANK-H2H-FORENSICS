# Issue Labels and Triage Guide

## Suggested Labels

### Type
- bug
- enhancement
- documentation
- question

### Priority
- priority-low
- priority-medium
- priority-high

### Area
- parser
- security
- evidence
- reporting
- workflow
- testing

### Status
- needs-triage
- confirmed
- blocked
- help-wanted

## Triage Process

1. Confirm the report is in project scope.
2. Check for duplicate issues.
3. Remove or request redaction of sensitive information.
4. Reproduce using sanitized files or fixtures.
5. Identify affected component.
6. Assign appropriate labels.
7. Document findings.
8. Close only when resolved, explained, or out of scope.

## Privacy Rule

Never request or encourage users to post unredacted banking files, passwords, account details, tokens, or confidential transaction evidence in public issues.
